# 观察池 V1.1 实施说明（研究分支）
- 冻结 V1.0 财务计算与财务版本选择；生产适配仅循环用户清单，不做全市场财务研究。沪深 A 股首版最多20只；初始为空，测试五家不自动加入。
- 不增加外部服务器、不在浏览器保存 GitHub PAT 或 Tushare Token。使用现有 RADAR_KEY 加密本地草稿与全量替换请求，GitHub 已登录的所有者在 Run workflow 选择 sync、粘贴密文。后台校验清单版本，重复旧请求或密钥认证失败不得修改清单。首次 bootstrap 产生空池与加密名录；refresh 仅刷新已有清单。
- 名录、清单、单股分片全部 AES-GCM 密文，分片名为密钥 HMAC 生成的 opaque slot，公开 Git 历史仍保留旧密文，文件数量及更新时间仍可观察。与现有 RADAR_KEY 同权限（共享密钥的设备也可读取）。没有端到端独立用户权限。
- 沿用 V2.1 IndexedDB 快照层，新增 watchlist、directory 与 company:opaque-id，单股独立缓存；15分钟版本检查，断网保留旧报告，错误不覆盖已认证报告。观察池草稿用原密钥加密保存；未保留原密钥备份时需本地输入原密钥以授权加密编辑，不能生成新密钥。明确采用后台清单可舍弃冲突草稿。
- 后台计划北京时间交易日21:30（实际调度可能延迟），仍只查询池内股票；首版每次刷新会重新读取池内财务历史和估值，后续可按披露变更优化。盘中手动任务采用上一完成行情日；同日成长扫描快照不可用时不生成同行参考。已移出股票停止生成且移除当前分片，历史密文不保证永久删除。
- 当前仅隔离研究分支，不写 main、不执行正式观察池初始化或调度。测试流程以五个已验证样本模拟，真实清单由用户后续自行添加。手机端真实授权流程、GitHub Actions 手机界面与主分支发布需上线前验证。
